## 1.0.0 (2026-09-07)

### Added

- v1.0.0 mint of the `platform-cloudflare-durable-objects` blueprint, category `platform`, capabilities `["strongConsistencyCell", "hibernatableWebSocket"]`. Ships two composable shapes: the SINGLE-CELL shape (a named object as an authoritative counter, session store or lock) and the WEBSOCKET-HUB shape (a named object hosting many websocket clients with per-message routing and hibernate-and-wake support). One DO facade module owns the DO namespace bindings; typed storage API wraps both SQL and KV backends; alarm surface fires exactly once per scheduled time; hibernatable-WebSocket shape realises Cloudflare's documented hibernate-and-wake contract.
- 8 REQs (`platform-cloudflare-durable-objects-REQ-001..008`), 13 USs (`platform-cloudflare-durable-objects-US-33101..33113`; US-33113 covers the wrangler-seam runtime coverage), 5 TACs (`TAC-3401` namespace facade, `TAC-3402` single-cell shape, `TAC-3403` alarm handler, `TAC-3404` websocket hub, `TAC-3405` lifecycle event sink), 5 ADRs (`ADR-3401` scope-global on new topic `strongConsistencyCellContract` with `standardsTraceClause: Cloudflare Durable Objects documented consistency model`; `ADR-3402` scope-global on new topic `websocketHubContract` with `standardsTraceClause: Cloudflare Durable Objects hibernatable WebSockets shape`; `ADR-3403` storage backend `elicited: true` `recommendedDefault: sql`; `ADR-3404` migrations-shape with `standardsTraceClause: Cloudflare Durable Objects migration documentation`; `ADR-3405` hibernation posture `elicited: true` with idempotent-by-contract wake handler).
- 8 Node-only probes under `contributions/probes/`: `namespace-facade-ready` (facade opens and emits namespaceReady with metadata-only payload), `single-cell-concurrent-increment` (two concurrent increments serialise FIFO; also folds AC-33109-1 witness field), `storage-round-trip` (both sql and kv backends; also folds AC-33111-1 default backend), `alarm-fires-once` (once-per-schedule contract with drained storage), `websocket-hub-broadcast` (fan-out within window; folds AC-33110-1 hibernate-and-wake and AC-33106-1 event-secrecy on the shipped path with SIMULATE_PII_LEAK=true mutation), `sole-reader-scan` (source-tree scan of the applied source root with comment-stripping; folds SIMULATE_NON_FACADE_IMPORT=true mutation), `real-account-storage-smoke` (`accountBound: true`; records `accountBoundSkipped` in CI without `CI_HAS_CLOUDFLARE_ACCOUNT` per spec section 3.5), and `wrangler-seam` (drives `wrangler dev --local` on the fixture; two concurrent POST /cell/<id>/increment requests through the DO facade reaching env.CELL observe per-instance serialisation; one WebSocket upgrade against /hub/<id>/connect through the facade reaching env.HUB receives one broadcast frame; additional AC-33108-1 result on the same run greps wrangler.toml for both binding pairs and the migrations tag/new_classes; warn semantics per section 3.1 pass-with-skip if wrangler is missing or fails to bind).

### Known limitations

- The `real-account-storage-smoke` probe records `accountBoundSkipped: true` and aggregates to `pass` when `CI_HAS_CLOUDFLARE_ACCOUNT` is unset (spec section 3.5 pass-with-skip). Full mechanism reach requires a CI environment with `CI_HAS_CLOUDFLARE_ACCOUNT=true` plus paired `CF_ACCOUNT_ID`, `CF_DO_NAMESPACE_ID` and `CF_API_TOKEN` env vars, and a deployed Worker exposing the DO facade round-trip.
- The v1.0.0 boundary defers RPC-style class methods, storage backups and multi-object transactions across namespaces to v1.1.0 per spec section 5.3. The shipped code path does not open any of these seams; the v1.1.0 minor lands them as an additive minor.
- The in-memory DO storage driver realises both `sql` and `kv` backends deterministically for the shipped probes; a real Cloudflare DO backend (SQL storage vs KV storage) may exhibit different edge-case semantics on the wrangler dev boot path. The real-account smoke covers the real-backend edge; the local probes cover the shipped code path.
- The hub-shape hibernate-and-wake round-trip in the shipped in-process probe uses a fake state object with `acceptWebSocket`, `getWebSockets` and a fake websocket pair. A real `wrangler dev` process hosting DO bindings would exhibit different hibernation timing behaviour; the guide notes the trade at self-review.
- The `_serialise` promise queue on the shipped SingleCellObject class is defence-in-depth against non-workerd runtimes. Under workerd's fetch path, per-instance input gates plus storage output gates serialise concurrent invocations against the same object, so removing the `_serialise` guard is not observable through the wrangler-seam probe unless an additional race window (for example an artificial delay between the storage read and write) is also introduced. The in-process `single-cell-concurrent-increment` probe DOES observe the `_serialise` removal on its own (Node without workerd's storage gate); mutation-check tails on both probes ride the PR body.
